# KotMail

KotMail 0.3 — небольшой read-only коннектор для цепочки:

`ChatGPT → OpenAI Secure MCP Tunnel → KotMail MCP → Yandex OAuth → IMAP/XOAUTH2`.

Проект рассчитан на один тестовый ящик и одного оператора. В нём нет отправки, удаления, перемещения, изменения флагов или папок.

Цепочка и все пять инструментов проверены через ChatGPT; KotMail также успешно использовался в автоматизации. В версии 0.3 добавлено безопасное локальное восстановление runtime после входа в Windows.

## Что реализовано

- Yandex device OAuth с правами `mail:imap_ro` и `login:email`; пароль Яндекса не запрашивается.
- Access token, refresh token, Client Secret и адрес ящика хранятся в локальном AES-256-GCM vault.
- IMAP подключается к `imap.yandex.com:993` через TLS и XOAUTH2.
- INBOX всегда открывается командой `EXAMINE` (`readOnly: true`).
- MCP работает через stdio на актуальном TypeScript SDK v2; внешнюю HTTPS-точку предоставляет OpenAI Secure MCP Tunnel.
- Все идентификаторы писем непрозрачны, подписаны HMAC и привязаны к `UIDVALIDITY`.
- Содержимое отдаётся отдельным tool: только текстовые MIME-части, без файлов вложений и вложенных писем. HTML переводится в текст без исполнения скриптов и загрузки ресурсов.
- Лимиты чтения: 50 000 символов, 1 МБ закодированных текстовых частей, максимум 8 частей. При обрезке возвращается `truncated: true`; `contentStatus: no_text_body` означает отсутствие поддерживаемого текста.
- Последние письма и поиск поддерживают продолжение через `beforeId`; поиск также поддерживает `unread`.
- Текст, заголовки и имена файлов обозначены в инструкциях сервера как недоверенные данные. Это подсказка модели, не замена отсутствию write-инструментов.

MCP tools:

| Tool | Данные | Лимит |
|---|---|---:|
| `mail_list_recent` | Последние метаданные INBOX | 25 |
| `mail_search` | Поиск по from/subject/text/date/unread | 25 за страницу |
| `mail_get_metadata` | Метаданные одного письма | 1 |
| `mail_get_content` | Plain-text одного письма | 1 |
| `mail_list_attachments` | Имя/MIME/размер вложений | 1 |

Скачивание вложений намеренно не включено в spike: сначала проверяется основная цепочка без передачи бинарных файлов.

### Примеры запросов

- «Через KotMail покажи 10 непрочитанных писем за неделю, только отправитель, тема и дата».
- «Найди во входящих письма от … со словами … в теме».
- «Покажи следующую страницу результатов».
- «Прочитай письмо из второго пункта и кратко перескажи».
- «Какие вложения в этом письме? Не скачивай файлы».

Фильтры поиска соединяются **И**. `text` — IMAP TEXT (заголовки и тело), не семантический поиск. Даты фильтруют календарный день получения по IMAP: `after` включительно, `before` исключительно. Сортировка — новые поступления первыми по UID, не по дате отправителя. Для следующей страницы передайте `nextBeforeId` как `beforeId`, сохранив остальные фильтры. `hasMore: false` завершает выдачу. Это не неизменяемый снимок: внешние удаления и изменение прочитанности влияют на результаты.

## Почему здесь нет публичного callback и собственного HTTPS

Для локального spike используются два официальных механизма:

1. Yandex device OAuth: пользователь вводит одноразовый код на странице Яндекса, поэтому redirect/callback не нужен.
2. OpenAI Secure MCP Tunnel: `tunnel-client` сам создаёт исходящее HTTPS-соединение к OpenAI и запускает локальный stdio MCP. Входящий порт и публичный сервер не нужны.

Это сознательное упрощение только для одного тестового ящика. Для постоянной многопользовательской эксплуатации потребуется публичный HTTPS MCP, отдельная авторизация ChatGPT → KotMail и callback Яндекс OAuth на стабильном домене.

## Локальная подготовка

Требуется Node.js 24+.

```powershell
npm install
npm run bootstrap
npm run check
npm test
```

`bootstrap` создаёт `.env.local` с новым случайным master key. `.env.local` и `data/` исключены из Git.

После регистрации приложения Яндекса запустите:

```powershell
npm run setup
```

Откройте показанный локальный адрес `http://127.0.0.1:3210`, вставьте Client ID и Client Secret, затем подтвердите OAuth по ссылке Яндекса. Страница сама сохранит токены и проверит readonly IMAP. Повторная проверка:

```powershell
npm run verify
```

## Secure MCP Tunnel

В Windows дважды щёлкните **Start KotMail.cmd** в папке проекта. Он собирает код, если локальная страница ещё не запущена, запускает её скрытым фоновым процессом и открывает браузер. PowerShell и изменение политики выполнения скриптов не требуются. Повторный запуск использует уже работающую страницу.

Из терминала также доступно:

```powershell
npm run tunnel:setup
```

На `http://127.0.0.1:3211/` прежний Tunnel ID подставляется из локального состояния клиента. Введите runtime API key и нажмите «Запустить / перезапустить KotMail». Не вставляйте ключ в чат или командную строку. Кнопка перезапускает только alias `kotmail`, загружая собранную версию MCP; текущие вызовы могут прерваться.

По желанию отметьте «Автоматически восстанавливать KotMail после входа в Windows». Тогда runtime key сохраняется только в виде Windows DPAPI ciphertext, привязанного к текущей учётной записи Windows, а в пользовательский автозапуск добавляется небольшой watchdog. Он проверяет туннель и восстанавливает его после перезагрузки или остановки процесса. Сама локальная страница для этого постоянно работать не обязана. Опцию можно отключить на той же странице: запись автозапуска и зашифрованный ключ удаляются, текущий туннель продолжает работать.

Это защищает ключ от случайного чтения файла и попадания в репозиторий, но не от вредоносной программы или администратора, уже работающих от имени этого пользователя Windows. Используйте отдельный ограниченный runtime key только с Tunnels Read + Use и при подозрении на компрометацию отзывайте его в OpenAI Platform.

Страница проверяет текущее состояние каждые 5 секунд, показывает время проверки и обрабатывает потерю связи. Зелёный индикатор подтверждает здоровье туннеля, но не проверяет Яндекс или версию MCP в ChatGPT. Локальные формы защищены проверками Host/Origin и CSRF.

После изменения MCP-контрактов: перезапустите через форму, откройте существующее подключение KotMail в ChatGPT → **Refresh / Обновить**, затем начните новый чат. Это [официальный порядок обновления метаданных](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata). Создавать новое приложение Яндекса или новый туннель не нужно.

В форме ChatGPT для этой частной тестовой версии выбирайте **без аутентификации**, а не OAuth: отдельный OAuth-сервер ChatGPT → KotMail не реализован. Это не отключает Yandex OAuth внутри KotMail.

В ChatGPT создайте developer-mode app, выберите **Tunnel** и созданный tunnel. Для spike используйте личное workspace или workspace, доступное только тестеру: KotMail хранит ровно один ящик, поэтому любой пользователь, которому доступен этот app/tunnel, получает те же readonly возможности.

## Ручные действия пользователя

Только действия, требующие входа в интерфейс владельца аккаунта:

1. В Яндекс OAuth создать приложение для API/отладки и дать только `mail:imap_ro` и `login:email`; скопировать Client ID/Secret в локальную страницу KotMail.
2. В настройках Яндекс Почты включить IMAP и способ входа «Пароли приложений и OAuth-токены».
3. На странице Яндекса ввести выданный KotMail код и подтвердить доступ.
4. В OpenAI Platform создать Secure MCP Tunnel/runtime key, затем в ChatGPT developer mode подключить готовый tunnel как app.

## Проверки

`npm test` — синтетические тесты без подключения к почте, с отдельным тестовым ключом. На Windows дополнительно проверяется реальное шифрование/расшифровка DPAPI синтетического runtime key. `npm run check` — проверка типов.

`npm run smoke:mcp` — живой запрос метаданных. `npm run smoke:all` — вызовы всех пяти tools: страницы, непрочитанные, метаданные, чтение одного письма, список вложений, поиск по отправителю/теме/датам/тексту, сравнение `seen` до/после. Используйте только на разрешённом тестовом ящике: расширенная проверка действительно читает одно тело в память. Выводит статусы и размеры, не письма, адреса, ID или ключи. Пустой ящик не позволяет выполнить эту живую проверку.

## Граница spike

Это не production multi-tenant connector. Только INBOX одного ящика. Нет публичной публикации, скачивания вложений, фоновой синхронизации, индекса, SMTP и любых write-операций. Компьютер должен быть включён, интернет и runtime туннеля — доступны.
